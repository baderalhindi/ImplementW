Each migration touches one module's schema (`Migrations/README.md` R-7). So `identity_access` is created first without the three foreign keys that leave it. A fourth migration adds those keys once their targets exist.

Every migration was generated by `dotnet ef migrations add` from the model. Two edits were made by hand, both before the branch left the machine (R-3):
- Each class got a summary.

Each Down drops what its Up created and nothing else. `MigrationRollbackTests` confirms this against PostgreSQL.

**Totals across the three schemas:** 34 tables, 418 columns, 70 foreign keys (19 cross a schema, all to a referenceable table per D-14), 82 non-primary indexes (33 unique) and 43 CHECK constraints.

## 3. How the ERD conventions became SQL

| ERD rule | Implementation |
| --- | --- |
| D-1 `id uuid` key | `AuditedEntity.Id` in `Domain/Common`. The value is generated by the application; the column has no default |
| D-2 audit columns | `AuditedEntity` carries the four columns, all non-nullable types, so all `NOT NULL`. `_by` columns have no FK. APPEND_ONLY tables (`project_intake`, `project_intake_milestone`) get `CHECK (updated_at = created_at AND updated_by = created_by)` |
| D-4 names | `UseSnakeCaseNamingConvention` (TASK-024). Entity = PascalCase(table), except the C# alias `ProjectEntity` used only inside configurations, where the namespace `…Configurations.Project` would shadow the type |
| D-5 money | `Money` maps through `MoneyConverter` to `numeric(18,2)` by model convention. Property names end in `Sar`, so columns end in `_sar`. No currency column |
| D-6 bilingual labels | `BilingualLabel` is an EF complex property mapped to `<name>_ar`/`<name>_en varchar(200)`. An optional pair also gets `CHECK ((x_ar IS NULL) = (x_en IS NULL))` |
| D-7 narrative | `NarrativeText` is a complex property mapped to `<field> text` and `<field>_lang char(2)`. An optional pair gets the same both-or-neither CHECK |
| D-12 governed lifecycle | `GovernedEntity` (`Domain/Common`) carries the six columns. `HasGovernedLifecycle()` declares the reviewer and publisher FKs to `user` |
| §6 state columns | Each state or type column is a C# enum stored as its upper-snake-case name (`UnderReview` → `UNDER_REVIEW`, `EnumTextConverter`). A model-finalizing convention (`ValueSetCheckConstraintConvention`) gives **every** enum and language column a CHECK listing its values, so no such column can be left unconstrained |
| D-3 delete policy | FK `ON DELETE CASCADE` only from a CASCADE-class child to its parent (18 FKs, e.g. `configuration_value` → `configuration_version`). Every other FK is `ON DELETE RESTRICT`: RETAIN rows are never deleted, and a HARD_DRAFT project with dependants cannot be removed from under them |
| Defaults | `erd.dbml` defaults are database defaults. `HasDatabaseDefault` sets the EF sentinel to the default itself. With the CLR default as sentinel, setting `is_active = false` on a column that defaults to `true` would silently store `true` |

CHECK rules the ERD states in notes, not as types:

| Table | Rule | Source |
| --- | --- | --- |
| `user` | `user_type <> 'EXTERNAL' OR external_entity_id IS NOT NULL` | erd.dbml: "Required when user_type = EXTERNAL" |
| `user` | `mobile_number` matches E.164 `^\+[1-9][0-9]{1,14}$` | ADR-004; erd.dbml |
| `project` | `formal_project_id` present from APPROVED_PLANNED onwards | TASK-041: issued on AHDA approval |
| `impact_level_definition`, `probability_level_definition` | `level BETWEEN 1 AND 5` | ADR-011, PTBC-017 |
| `risk_matrix_cell` | both levels `BETWEEN 1 AND 5` | ADR-011 5×5 |
| `materiality_band`, `approval_authority_rule` | `band_no BETWEEN 1 AND 3` | ADR-016 |

## 5. Normalisation review against the ERD

`CoreSchemaTests.TheCoreSchemaIsTheCanonicalErd` checks that the migrated schema matches `erd.dbml`: the same tables, columns, types, nullability, unique keys and foreign keys. So this review of the ERD's 34 tables is also a review of the schema. The tests treat 3NF as follows:
- **Repeating groups:** a list is never a set of numbered columns.
- **Partial dependency:** a single-column surrogate key (D-1) leaves none possible.
- **Transitive dependency:** no non-key column is determined by another non-key column. A business key such as `code` is a candidate key, and depending on it is allowed.

`TheDatabaseRejectsRowsThatBreakAnErdRule` inserts nine rows, each breaking one rule, and expects the database to refuse each one:
- an unknown lifecycle state;
- a `fr` language tag;
- an approved project with no Formal Project ID;
- impact level 6;
- matrix probability level 0;
- a half bilingual pair;
- an EXTERNAL user with no entity;
- an update to an APPEND_ONLY row;

A baseline row with none of these defects is accepted, so each refusal is caused by its rule, not by a broken insert.

## 7. Local stack

The bridge schema `infra/docker/postgres/init/01-schema.sql` is deleted (`local-development-environment.md` F-2). `local-stack-check.py`, which guarded it against drift, is deleted with its CI step; `TheCoreSchemaIsTheCanonicalErd` now guards the real schema against `erd.dbml` in the `backend` job.

Compose starts in this order: `postgres` healthy → `migrate` (the API image with `migrate`, as each environment's Cloud Run job does) → `seed` (`psql` on `infra/docker/postgres/seed/*.sql`, which are the former `02-`/`03-` scripts, unchanged apart from their headers) → `api`. Both one-shots exit 0 on every `up`, since the migrations are applied once and the seed is idempotent.

The API's `DB_CONNECTION_STRING` host is `postgres`, the service name. `localhost` inside a container is the container itself, so the value on `dev` could not reach the database.

`smoke-test.sh` from a reset volume: **PASS**. All services were healthy in 14 s (build 9 s), `/health` returned 200, and there is one active local user per role R01–R08. The seed was also run twice on a freshly migrated scratch database, with identical counts after each run: 8 roles, 8 profiles, 8 versions, 9 users, 8 grants.

The TASK-023 drill scripts (`rehearse-restore.sh`, `run-restore-drill.sh`) built their source database from the deleted init directory. They now migrate and seed it the same way, and `drill-fixture.sql` creates `audit_activity` only if it is missing. They were syntax-checked, **not re-run** (G-6).

## 8. Findings

| # | Finding | Owner | Consequence if left |
| --- | --- | --- | --- |
| **N-1** | **`project.region_item_id` depends on `city_item_id`.** A city lies in exactly one region, so on a row with both, the region is a function of the city: a transitive dependency, and nothing stops the two disagreeing. Options: (a) store only the most specific location, with `CHECK (region_item_id IS NULL OR city_item_id IS NULL)`, and derive the region from the city item's parent; (b) keep both and enforce agreement in WF-01 validation (TASK-041); (c) add both to ERD §7 as a justified copy. Recommended: (a).
